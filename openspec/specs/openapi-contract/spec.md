# openapi-contract Specification

## Purpose
Defines the API's published OpenAPI document as a code-generation contract, so clients can generate readable, accurate types from it instead of hand-writing them.

## Requirements

### Requirement: Committed document tracks the contract
The API SHALL keep `artifacts/openapi/TacticusPlanner.Api.json` equal to the document the current code produces. It SHALL be regenerated by the build, and any change to a route, request or response SHALL be committed together with its regenerated document.

#### Scenario: Contract change ships with its document
- **WHEN** a change adds, removes or reshapes an endpoint's request or response
- **THEN** the same change commits the regenerated document
- **AND** building the API leaves the committed document unchanged

### Requirement: Short, unique schema names
Every component schema SHALL be named after its type alone, without namespace prefixes. Generic types SHALL be named from their short type and argument names. No two distinct types SHALL share a schema name.

#### Scenario: Response schema has a short name
- **WHEN** the document is generated
- **THEN** the goal detail response schema is named `GoalDetailResponse`
- **AND** no schema name contains a namespace prefix such as `TacticusPlanner` or `SystemCollectionsGeneric`

#### Scenario: Name collision is caught
- **WHEN** two distinct types would produce the same schema name
- **THEN** the API test suite fails and names both types

### Requirement: Nullable references keep their null
A property whose value is either null or a referenced schema SHALL be described so a generator reads it as "null or the referenced type" (a `oneOf` of `{type: null}` and the reference). It SHALL NOT be described as a `type` that includes null next to the reference, because generators turn that into an intersection that loses the null.

#### Scenario: Nullable object property
- **WHEN** the document is generated
- **THEN** the goal detail response's `snapshot` property is `oneOf: [{type: null}, {$ref: GoalSnapshotResponse}]`
- **AND** no schema anywhere in the document combines a null-including `type` with `oneOf`, `anyOf` or `$ref`

### Requirement: Query parameters are documented
Every query parameter a route reads SHALL appear in the document as a parameter of that operation, with its type.

#### Scenario: List and paging parameters
- **WHEN** the document is generated
- **THEN** `GET goals` and `GET projects` document the `archived` query parameter
- **AND** `GET legendary-event-plans/{eventId}/run-records` documents `limit` and `after`

### Requirement: Response properties are required
Every property of a planner response (`/api/v1/**` outside `game-catalog`) SHALL be listed as required, because the API always writes it (null included). Problem-details members that only some statuses carry are exempt. A response SHALL NOT expose a persisted storage type directly; it maps to its own response records.

#### Scenario: Goal detail
- **WHEN** the document is generated
- **THEN** `GoalDetailResponse` lists `revision` and `globalPriority` as required

### Requirement: Every schema has a shape
Every schema SHALL describe its shape: a type, properties, an enum or a composition, and arrays SHALL describe their items. Typed identifiers (value objects) SHALL be described as the primitive they are written as. Only raw JSON values may be shapeless.

#### Scenario: Value-object identifiers
- **WHEN** the document is generated
- **THEN** `UnitId` is a string schema and a list of campaign battle ids is an array of strings

### Requirement: Fixed-value fields are string enums
A request or response field whose values come from a fixed set SHALL be described as a string schema that lists every allowed value. Examples are goal status, goal type, entity type and farming strategy.

#### Scenario: Goal status lists its values
- **WHEN** the document is generated
- **THEN** the goal detail response's `status` property is a string enum of `Active`, `Paused`, `Completed`, `Archived`

#### Scenario: A fixed-value field typed as plain string is caught
- **WHEN** a request or response field backed by an enum is described as an unconstrained string
- **THEN** the API test suite fails and names the schema and property

### Requirement: Enum wire values are stable
Enum fields SHALL serialize to the same PascalCase strings the API returned before this change. Requests SHALL accept those values case-insensitively. A request with a value outside the set SHALL be rejected with a 400 `validation` problem whose `errors` names the field, and SHALL change nothing.

#### Scenario: Response values are unchanged
- **WHEN** a client reads a goal
- **THEN** `status`, `goalType` and `entityType` carry the same strings as before (e.g. `Active`, `Rank`, `Character`)

#### Scenario: Lower-case request value is accepted
- **WHEN** a client creates a goal with `"entityType": "character"`
- **THEN** the goal is created with entity type `Character`

#### Scenario: Unknown value is rejected by field
- **WHEN** a client creates a goal with `"goalType": "teleport"`
- **THEN** the API answers 400 with issue code `validation`
- **AND** `errors` has an entry whose key ends with `goalType`
- **AND** no goal is created
